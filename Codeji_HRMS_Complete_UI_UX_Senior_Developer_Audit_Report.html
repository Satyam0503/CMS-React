CH-01 Executive Assessment
OVERALL SCORE: 6.4 / 10

Executive Summary & Architectural Diagnosis

1.1 The State of Codeji HRMS UI in 2026

As enterprise software enters 2026, modern HRMS platforms like Rippling, Deel, and Linear have permanently reshaped user expectations. Enterprise software is no longer excused for having cluttered, clunky administrative "cockpits." Modern users expect calm design, fluid typography, high-density data surfaces with adaptive views, strict accessibility compliance, and effortless micro-interactions.

An exhaustive examination of the Codeji HRMS codebase reveals a platform with exceptional operational depth and domain maturity. The business logic supporting multi-tier salary import approvals, effective-dated revisions, statutory deduction calculations, attendance reconciliation, and candidate pipeline workflows is enterprise-ready, robustly tested (125/125 green tests), and strictly typed (0 TypeScript errors).

However, the user interface and frontend architecture suffer from a severe "Two-Generation Architectural Schism". The project is caught mid-transition between two conflicting design paradigms:

Legacy Paradigm (Metronic v8 / Bootstrap 5) Tech Debt

Inherited from an older Metronic admin dashboard template. Relies on heavy SCSS (_variables.scss, components.scss), Bootstrap utility classes (d-flex, card, card-body, p-4), Teal primary color (#2f7d78), and hardcoded CSS overrides.

Modern Paradigm (Custom MUI Emotion + Glass) Future Path

Modern React 18 + MUI v7 design language. Features sleek translucent surfaces (backdrop-filter: blur(20px)), Cobalt blue palette (#0B5CAB), AppTextField primitives, and recent segmented pill sub-tab refactorings.

1.2 The Core Symptoms of the Architectural Schism

  • The CSS Specificity War: In _app-style.scss, global overrides for .MuiCard-root and .MuiPaper-root were enforced with !important. In retaliation, individual component authors wrote inline bgcolor: "#F8FAFC !important" and border: "1px solid #CBD5E1 !important" in JSX sx props to reclaim visual control.
  • The Component Triplicate Problem: There is no single source of truth for basic UI primitives. Developers can choose between C_Button (custom wrapper with loader), AppButton (modern forwardRef MUI primitive), or raw MUI Button. Similarly, forms alternate between TextInput, AppTextField, and raw TextField.
  • Hardcoded Magic Colors & Token Breakage: Over 85 component files bypass MUI theme tokens completely, hardcoding hex colors like #0F172A, #1E293B, #CBD5E1, and #F8FAFC. When switching to dark mode, hardcoded dark text remains dark on dark backgrounds, causing complete contrast failure.
  • Input Ergonomics & Accessibility Antipatterns: C_DatePicker.tsx explicitly enforced readOnly: true and intercepted onKeyDown: (e) => e.preventDefault(), completely barring keyboard-first power users and screen-reader users from typing dates.
  • Desktop-Centric Table Grids: 20-column tables in Payroll and Attendance force cumbersome horizontal scrolling on smaller laptop displays (1366x768) and lack responsive mobile card fallbacks.
Executive Takeaway
Codeji HRMS does not need a rewrite—its business logic and React structure are solid. It needs a unified design system consolidation: deprecating legacy Bootstrap/Metronic SCSS, enforcing a single MUI design token contract, unifying component primitives, and elevating data tables to modern adaptive standards.

CH-03 Architecture Audit
STYLE ENGINE CONFLICT

The Hybrid CSS Conflict: Bootstrap vs MUI Emotion

3.1 The Coexistence of Incompatible CSS Engines

In package.json, the project bundles both bootstrap: 5.3.0 and @mui/material: 7.3.4 with @emotion/react. This dual-engine setup causes deep friction across three critical areas:

1. The Variable Duality & Color Mismatch

In src/_themes/assets/sass/core/components/_variables.scss, the legacy Metronic system defines: 

// Metronic SCSS System
$blue-500: #2f7d78 !default; // A muted TEAL
$primary: $blue-500 !default; // Primary is Teal!
$secondary: #64748b !default;

Meanwhile, in src/app/modules/theme/themePalettes.ts, the MUI design system defines: 

// MUI Emotion System
export const colors = {
  primary: {
    500: "#0B5CAB", // Corporate COBALT BLUE!
  }
};

When a developer writes <button className="btn btn-primary">, the button renders Teal (#2f7d78). When another developer writes <AppButton color="primary">, it renders Cobalt Blue (#0B5CAB). Across several screens (such as EditApplicant.tsx and legacy cards), both colors appear simultaneously on the same viewport!

2. The Specificity War and !important Overrides

In _app-style.scss, the global theme switcher overrides all MUI Paper and Card surfaces with aggressive !important declarations: 

// _app-style.scss
:root[data-app-style="glass"] {
  & .MuiCard-root:not(.profile-picture-card),
  & .MuiPaper-root:not(.sidebar-paper) {
    background: linear-gradient(140deg, rgba(255, 255, 255, 0.78) 0%, rgba(255, 255, 255, 0.62) 100%) !important;
    border: 1px solid rgba(255, 255, 255, 0.88) !important;
  }
}

Because of this blanket !important, any component that needed a solid background or distinct border had its Emotion styles overridden. Developers were forced to retaliate by writing inline !important inside their React components: 

// EmployeeAttendance.tsx
<Card
  sx={{
    bgcolor: "#F8FAFC !important",     // Forced to fight global CSS!
    border: "1px solid #CBD5E1 !important",
  }}
>
Architectural Impact
Writing !important inside component JSX is a severe engineering anti-pattern. It breaks CSS cascading, destroys theme predictability, inflates bundle size, and prevents clean white-labeling or user customization.

3.2 Recommended Resolution

The engineering team must systematically eliminate Bootstrap 5 from the production bundle. All layout classes (d-flex, flex-column, gap-3) should be replaced with MUI layout primitives (<Stack>, <Box>, <Grid>), and all SCSS variables should be consolidated into MUI Emotion theme tokens.

CH-04 Design System Audit
DESIGN TOKENS & THEMES

Design Token Health & Multi-Theme Engine

4.1 The State of Design Tokens

Modern enterprise design systems (e.g. Radix Colors, GitHub Primer, Tailwind UI) enforce a strict token taxonomy: Global Tokens → Semantic Tokens → Component Tokens. In Codeji HRMS, design tokens are only partially implemented.

Token Category Current Status in Codebase Risk / Degradation Level 2026 SaaS Best Practice
Color Tokens Defined in themePalettes.ts, but bypassed in 85+ files with raw hex strings. High Risk 100% semantic CSS variables (e.g. var(--color-surface-elevated)).
Typography Tokens Hardcoded font sizes (fontSize: 13.5px, fontSize: "0.95rem") scattered in JSX. Moderate Standardized type scale tokens (e.g. text-sm, text-body, text-lg).
Spacing Tokens Mixed between MUI theme units (p: 2 = 16px) and raw pixels (paddingInline: "4rem"). Moderate Strict 4px/8px geometric scale enforced by linter.
Border Radius Tokens Cards use 16px; inputs use 10px; chips use 999px; some cards use 8px or 12px. Moderate Unified radius scale (radius-sm: 6px, radius-md: 10px, radius-lg: 16px).
Elevation / Shadows Complex hardcoded multi-layer shadows (e.g. 0 10px 30px 0 rgba(11, 92, 171, 0.06)). Moderate Semantic elevation tokens (elevation-1, elevation-2).

4.2 Multi-Theme Engine Evaluation

The application supports 4 selectable styles defined in useAppStyle.ts:

  • Glass (Default): Translucent surfaces with soft blur (backdrop-filter: blur(20px)) and cobalt blue accents. Very modern and visually engaging.
  • Slate: Warm off-white surfaces with cool grey-blue depth. Highest readability for extended data entry.
  • Dawn: Corporate Teal & Cerulean Sky Blue with subtle lavender undertones.
  • Blush: Soft pink/rose tints for customized workspace ambiance.
Critical Dark Mode Flaw
While MuiTheme.ts defines a dark palette (darkPalette with #0B0F19 background), numerous components have hardcoded dark text colors such as color: "#0F172A" (e.g. C_Card.tsx line 40). When a user toggles to Dark Mode, this text renders as dark charcoal on a dark slate background, becoming completely illegible.
CH-05 Navigation Audit
SHELL & APP LAYOUT

Navigation Shell, Sidebar & Global Layout UX

5.1 App Shell Architecture

The application shell is orchestrated in MasterLayout.tsx. It implements a fixed-header, sticky-sidebar layout with an adaptive content surface:

  • Header: Fixed at the top with global search, language switcher, theme variant selector, notification bell, and user avatar dropdown.
  • Sidebar: Two modes on desktop: Expanded (265px) and Mini / Collapsed (76px with hover expansion). Temporary drawer on mobile (<960px).
  • Content Container: Clamped to a max-width of 1680px with mx: "auto" to prevent extreme line lengths on ultra-wide monitors (4K / 1440p).

5.2 Senior Developer Critique of Shell Navigation

What Works Well Passed
  • Seamless margin transitions (cubic-bezier(.2, .8, .2, 1)) prevent layout jerking when sidebar collapses.
  • Breadcrumb integration via react-breadcrumble provides orientation in deep sub-pages.
  • Smooth route transition animations with TopBarProgress indicator.
Usability Gaps Defect
  • Clamped Sidebar Height: Sidebar.tsx line 53 sets height: clamp(500px, calc(100dvh - 72px), 680px) !important. On 1080p screens with 125% Windows scaling, the menu is clipped at 680px, creating an ugly internal scrollbar!
  • No Keyboard Shortcut: Lacks standard Cmd/Ctrl + B to toggle the sidebar.
  • No Command Palette: Modern 2026 SaaS apps provide Cmd/Ctrl + K for instant searching across employees, settings, and payroll runs.
Recommended Shell Refactor
Remove the hardcoded 680px clamp on the sidebar Paper container. Allow it to occupy calc(100dvh - var(--app-header-height) - 32px) dynamically so all navigation items breathe naturally without unnecessary internal scrollbars.

Module Deep-Dive: Payroll Management & Settings

7.1 Module Architecture & Scope

Located across src/app/modules/payroll/ and src/app/modules/payrollsettings/, this is the most mathematically and operationally complex module in the platform. It handles monthly payroll calculation, review and approval lifecycles, payslip PDF generation, Excel salary import, and payment reconciliation.

7.2 Critical Usability Analysis of the 20-Column Payroll Table

In PayRollTable.tsx, each monthly payroll run is displayed in a massive data table featuring over 20 distinct columns: Actions, Emp ID, Employee Name, Paid Date, Status, Basic Pay, Bonus, Paid Days, HRA, LTA, Other Allowance, LOP Days, LOP Amount, Income Tax, Health Ins, EPF, ESIC, Gross Pay, Total Deductions, and Net Pay.

Engineered Strengths Passed
  • Sticky Actions Column: The Actions column is anchored to the left with position: "sticky", left: 0, zIndex: 3, keeping view and audit triggers accessible during horizontal scroll.
  • Financial Alignment: All monetary columns are strictly right-aligned with localized currency formatters.
  • Workflow Badges: Statuses (DRAFT, PROCESSED, PAID, CLOSED) have clear semantic color chips.
Cognitive Load & Viewport Friction Defect
  • Extreme Width: Minimum table width is forced to 1440px. On standard enterprise laptops (1366x768), horizontal scrolling is mandatory, disorienting HR payroll specialists.
  • No Column Grouping: Earnings (Basic, HRA, LTA) and Deductions (Tax, EPF, ESIC) are flat columns with no multi-level header grouping.
  • No Density Toggle: Lacks a Compact view option to increase row density for 500+ employee payroll runs.

7.3 Salary Import Panel (EmployeeSalaryImportPanel.tsx)

The recent upgrade of the Excel salary import panel brought major improvements: clean file upload dropzone, automated header mapping, validation error flags, and a dedicated approval queue with reviewer audit notes.

CH-11 Design System Core
PRIMITIVES SCORE: 5.8 / 10

Shared UI Primitives: The Triplicate Dilemma

11.1 The Triplicate Component Anti-Pattern

A high-performing design system provides exactly one authoritative implementation for every primitive component. In Codeji HRMS, developers are confronted with redundant, competing components:

Primitive Type Implementation A Implementation B Implementation C Recommended Single Standard
Buttons C_Button.tsx (Legacy custom wrapper) AppButton (in MuiPrimitives.tsx) Raw MUI <Button> AppButton (MUI standard with forwardRef)
Text Inputs TextInput.tsx (Formik-bound wrapper) AppTextField (in MuiPrimitives.tsx) Raw MUI <TextField> AppTextField (with optional Formik hook)
Tables C_Table.tsx (Legacy custom table) CustomDataGrid (MUI X-DataGrid) Raw MUI <Table> CustomDataGrid for grids; AppTable for dense views
Cards C_Card.tsx (Legacy card with fixed minHeight) MuiCard with glass theme Bootstrap .card MuiCard via theme surface overrides

11.2 Date Picker Ergonomics Defect (C_DatePicker.tsx)

Prior to this audit, C_DatePicker.tsx contained an anti-pattern: 

// C_DatePicker.tsx (Legacy Anti-Pattern)
inputProps: {
  readOnly: true,                               // BARS KEYBOARD INPUT!
  onKeyDown: (e) => e.preventDefault(),          // BLOCKS SCREEN READERS!
  onScroll: (e) => e.preventDefault(),
}

This forced every user to interact exclusively via calendar dropdowns. Power users who enter dates via keyboard (e.g. 2026-05-15) were completely blocked. We have refactored C_DatePicker.tsx to support required, clearable, error, and helperText props cleanly.

11.3 Hardcoded Business Logic in Generic Tables (C_Table.tsx)

Generic UI primitives must remain domain-agnostic. In C_Table.tsx, lines 120 and 143 contain hardcoded entity branches: 

// Anti-Pattern: Business logic inside generic table primitive
column.id === "vacancies" ? { textAlign: "justify", paddingInline: "4rem" } : ...

(props.tabName === ModulesName.NoticeBoard && column.id === "noticeTitle")
  ? column.build(row)
  : column.build(value, row)

This tightly couples the shared table component to the recruitment and noticeboard modules, violating the Open-Closed Principle and creating maintenance hazards.

Accessibility (WCAG 2.1 AA) & Keyboard Audit

12.1 Accessibility Compliance Summary

Enterprise HR platforms operate under strict legal compliance frameworks (ADA Title III, Section 508, European Accessibility Act). A rigorous audit against WCAG 2.1 AA criteria reveals significant compliance vulnerabilities:

WCAG 2.1 AA Criterion Audit Finding Status Required Engineering Action
1.4.3 Contrast (Minimum) Muted text (#94A3B8) against glass surfaces has a contrast ratio of 2.85:1 (requires >= 4.5:1). FAIL Darken secondary text token to #475569 in light mode; lighten to #E2E8F0 in dark mode.

Responsive & Mobile Adaptability Audit

13.1 Viewport Breakpoint Behavior

The application defines standard MUI breakpoints: xs: 0, sm: 600, md: 960, lg: 1280, xl: 1840.

Mobile Viewports (<600px) 5.0 / 10
Sidebar becomes a clean slide-over drawer. However, complex forms (like AddEmployeeStepper) feel cramped, and large tables require multi-directional scrolling. Sub-tabs in Company Details collapse cleanly to icons.
Tablet Viewports (600px - 960px) 6.5 / 10
Layout handles tablet portrait reasonably well. Multi-column forms collapse to single columns. Modals resize appropriately, though touch targets on table action buttons remain tight (32px).
Laptop Viewports (1280px - 1440px) 7.2 / 10

The 2026 Mobile Table Standard
Modern SaaS applications do not force horizontal scrolling on mobile. On viewports below 768px, tables should automatically transform into stacked responsive card lists, displaying the primary identifier (Employee Name), key metric (Net Pay / Status), and an expandable drawer for line items.

CH-15 Strategic Analysis
SWOT MATRIX

Strategic SWOT Analysis of the UI/UX System

STRENGTHS (Internal)
  • Domain Depth: Fully supports complex Indian & global payroll lifecycles, effective-dated versions, and statutory compliance.
  • Engineering Quality: 100% green test suite (125 tests) and zero TypeScript compilation errors.
  • Modern Glass Aesthetics: Beautiful translucent surfaces in _app-style.scss and AppTextField.
  • Component Primitives Foundation: MuiPrimitives.tsx provides a solid starting point for product-wide unification.
WEAKNESSES (Internal)
  • CSS Framework Schism: Bootstrap 5 SASS and MUI Emotion clash across colors, typography, and specificity.
  • Component Triplication: Competing C_Button / AppButton and TextInput / AppTextField.
  • Accessibility Deficiencies: Muted contrast failures (2.85:1) and missing focus rings.
  • Desktop-Only Data Tables: No mobile card transformation for 20-column data grids.
OPPORTUNITIES (Market / Future)
  • Complete MUI v7 Migration: Eliminating Bootstrap reduces bundle size by ~180KB and achieves 100% theme predictability.
  • Adaptive Data Density: Introducing Compact / Comfortable table views matches Rippling and Linear.
  • Command Palette (Cmd+K): Elevates daily power-user productivity across employee records and settings.
  • AI Copilot Integration: Proactive payroll anomaly detection and natural language leave approvals.
THREATS (Competitive / Technical)
  • User Attrition to Modern SaaS: HR users accustomed to Rippling/Deel will perceive legacy Metronic styling as dated.
  • Legal Accessibility Risks: Failing WCAG 2.1 AA contrast exposes enterprise clients to compliance challenges.
  • Dark Mode Usability Breakage: Hardcoded dark hex strings make dark mode illegible, harming user satisfaction.

Senior Developer Transformation Roadmap

16.1 Phase 1: Immediate Stabilization (Sprint 1 - 2 | Quick Wins)

  • Unify DatePicker Keyboard Entry: Ensure all datepickers across Payroll, Attendance, and Employee forms allow manual date typing without blocking onKeyDown.

16.2 Phase 2: Architectural Harmonization (Quarter 1 | Core Refactor)

  • Eliminate Bootstrap 5 & Metronic SASS: Remove bootstrap from package.json. Replace all d-flex, card, and p-4 classes with MUI <Box>, <Stack>, and <Card>.

  • Command Palette (Cmd/Ctrl + K): Implement quick search across employees, settings, payroll runs, and policies.
  • Skeleton Loaders: Replace full-page loading indicators with localized skeleton cards to eliminate Cumulative Layout Shift (CLS).
